## 2. Risk Analysis & AI-Generated Debt

Because this codebase was largely generated by AI, there are specific quirks, risks, and technical debts you need to be aware of:

### A. Simulated Backend Logic (Dev-Only Mocks)
*   **The Debt**: Files like [hooks/useAuth.ts](file:///c:/Users/kumar/Desktop/erp/src/hooks/useAuth.ts) and various page submits use `setTimeout` and pre-populated lists in `localStorage` to simulate API traffic.
*   **The Risk**: When it comes time to connect this app to a real production backend, you will need to replace these mocked timeouts with actual Axios API calls (e.g., `api.post('/auth/login')`). Make sure you don't build production code that relies on these mock responses!

### B. Rigid Zod Validations
*   **The Debt**: Validation schemas (like `loginSchema` or `signupSchema`) have strict length requirements or regex rules.
*   **The Risk**: If you test forms using simple words like `admin` or test passwords, the forms will fail validation and refuse to submit. Always look at the `.tsx` schema definitions to know exactly what credentials are valid.

### C. Missing Core Database Logic
*   **The Debt**: There are no database tables or ORM migrations. Everything is simulated.
*   **The Risk**: If you clear your browser's history or cookie storage, all newly created leads, users, and profile edits will disappear instantly. This is completely normal for frontend-only mockups.

## 3. Five Rules for Safe Coding

1.  **Do NOT Edit `src/components/ui` Files**: These are low-level UI elements (like buttons or dialogue shells) generated by shadcn. If you need a new styled button, create a component outside `ui/` or use Tailwind classes to style it.
2.  **Verify TypeScript Interfaces**: If you add columns to a table or fields to a form, always update their corresponding TypeScript types (e.g., `UserRow` inside [components/tables/users/columns.tsx](file:///c:/Users/kumar/Desktop/erp/src/components/tables/users/columns.tsx)). Failing to do this will cause the Vite compiler to throw errors.
3.  **Always Check Routing Guards**: If you create a page and can't access it, make sure the route in `routes/index.tsx` is placed inside the correct route array (public dev routes vs protected dashboard routes).
4.  **Use the Notification System**: Don't use raw browser alerts (`alert('Success')`). Use the built-in `notify` service (`notify.success('Your message')`) to maintain a clean, premium user experience.
5.  **Use Path Aliases**: When importing files, don't use long relative paths like `../../../components/ui/button`. Use the `@` alias configuration like: `@/components/ui/button`. It keeps imports clean and resistant to folder reorganizations.
